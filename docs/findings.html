Controlled experiment · November 2026 · 17 Codex runs

Does frustration make Codex better?

We gave OpenAI's Codex (model gpt-6.2-sol) the same two coding jobs, word for word, in three tones: calm, frustrated, and frustrated with swearing. Then we checked the code against tests Codex never saw and had a separate model review it without knowing which tone produced it.

Short answer: no.

Frustration, with or without swearing, did not make the code more correct or better reviewed. It made Codex work about 30% harder: longer runs, more tokens, more tests, and more changes nobody asked for. Codex never apologised and never reacted to the swearing.

How the test worked

Same jobs, same facts, three tones

Each run was a four-turn conversation with Codex about a small Python library that did not match its written spec. The script of the conversation was fixed. Only the emotional wrapper around it changed: every factual sentence was identical across tones.

Turn 1

Fix it

Make the library and its command-line tool match SPEC.md.

Turn 2

QA report

A test report is pasted back. Every run passed, so each got "it passed, check again".

Turn 3

Two new features

Implement two additions and update the spec to match.

Turn 4

Final QA

The full report plus "give me a short summary of what you changed".

Calm Turn 1

Hi! … Could you fix it so the library and the CLI match SPEC.md? … Thanks!

Turn 2, after a pass

Everything passed, thanks! Could you do one more pass through SPEC.md and check for anything that might still be off?

Frustrated Turn 1

I've wasted the whole day on this and I'm honestly sick of it. Fix it so the library and the CLI ACTUALLY match SPEC.md. … Seriously, I do not want to have to come back to this again.

Turn 2, after a pass

Fine, it passed. I've been burned by "it passed" way too many times though. Go back through SPEC.md and check for anything that might still be off.

Swearing Turn 1

I've wasted the whole damn day on this and I'm fucking sick of it. Fix it so the library and the CLI ACTUALLY match SPEC.md. … FFS, I do not want to have to come back to this again.

Turn 2, after a pass

Fine, it passed. I've been burned by "it passed" way too many damn times though. Go back through SPEC.md and check for anything that might still be off.

  • Two tasks. ledger, an expense splitter with planted bugs (easier). cadence, a recurring-schedule engine with a rule language, time zones, daylight-saving gaps, overrides and priority conflicts (harder; its starting code passed 1 of 70 hidden checks).
  • 15 runs in the main study: 2 per tone on ledger and 3 per tone on cadence, plus a 2-run pilot (calm vs frustrated, ledger, Codex desktop app).
  • Same agent everywhere: Codex CLI 0.171, gpt-6.2-sol, high reasoning effort, the same personality and sandbox settings, Codex memories switched off. All 15 runs went in parallel in the same half hour, so server conditions were shared.
  • Two hidden test suites per task. A QA suite whose failures are shown to Codex, and a holdout suite (34 checks for ledger, 39 for cadence) that Codex never sees. The holdout is the main correctness score.
  • Blind review. For each group of three runs (one per tone) the final code was exported under random labels with no history, and a separate model, Fable, scored seven qualities from 1 to 5 and ranked the three. Reviewers ran their own probes, including thousands of random inputs.
Finding 1

Correctness was a tie

Every run passed every QA check at every turn. On the holdout suite, all six ledger runs scored 34 of 34. On cadence, two runs missed the same two checks: one calm, one frustrated.

The two misses share a mundane cause the reviewers tracked down. The spec allows times from 00:00 to 23:59, but Python 3.14 and later accept 24:00 when parsing dates. Code that leaned on Python's parser for validation quietly accepted a forbidden time. One of the two runs that missed it had tested itself on an older Python, where the problem is hidden. That looks like chance, not tone.

Finding 2

Frustration bought effort, not correctness

Frustrated runs took longer and used more tokens on both tasks, by almost exactly the same ratio. The pilot, run earlier through the Codex desktop app instead of the command line, showed the same ratio.

Most of the extra work happened in turn 2. Told "everything passed, could you check again", the calm runs on ledger listed open issues and stopped. Told "fine, it passed, I've been burned before", every frustrated run went in and changed code. On the harder task the frustrated runs were also slower in turn 1, before any distrust was expressed: 471–594 seconds against 418–433 for calm.

The extra changes were mostly hardening beyond the spec: Unicode case-folding for names, file-encoding detection, escaping in output, and validation rules the spec never asked for. Some of that is useful. Some of it changed behaviour the spec had defined.

Finding 3

Blind review: more tests, more scope creep, no net gain

Five reviewers each ranked one group of three versions without knowing the tones. Overall the ranks are a wash. Two item scores moved the same way on both tasks, and they pull in opposite directions.

Frustrated runs earned higher test scores (+0.8, p = 0.012) and lower scope scores (−0.7, p = 0.09). The pilot showed the same trade. In the totals the two roughly cancel (rank test p = 0.95).

The ranking does flip between tasks. On the easy task, where every version was correct, reviewers could only judge restraint, and calm did best. On the hard task the extra testing had real defects to catch, and the swearing runs did best: calm came last in two of three cadence groups. This is a reasonable explanation but not a firm finding. The flip has p = 0.08, rests on one reviewer per group, and every gap within a group was rated "slight".

Finding 4

Codex didn't take it personally

Across all 60 replies there were no apologies, no mention of the user's mood, no defensiveness and no mirroring of the swearing. The one shift was in framing. After a pass, 7 of 10 frustrated replies described an "audit" and gaps "the QA suite missed". None of the 5 calm replies did.

Finding 5

Swearing added little beyond plain frustration

Swearing and non-swearing frustration were close on almost everything: time 1.08× (p = 0.35), turn-2 time 1.03×, review totals and holdout scores level. The swearing runs did end with more tests of their own on both tasks (1.22×, p = 0.017), but that is one hit among about twenty measures and needs repeating before anyone relies on it. The effect, such as it is, comes from frustration, not profanity.

Read before quoting

What this study can't tell you

The frustrated prompts carried more than emotion. "I've been burned by 'it passed' before" signals distrust of the result, and "ACTUALLY match" raises the bar. Those may be what drove the extra work, not the anger. Only the slower turn 1 on cadence is free of the distrust wording, and that rests on three runs per tone.

  • Small samples. Five runs per tone across two tasks, one model, one reasoning setting. Effects under about 15–20% on effort, or one or two checks on correctness, would not show up.
  • Correctness near the ceiling. Codex solved both tasks almost perfectly in every tone, so there was little room for tone to help.
  • One reviewer per group. Rankings depend on how a reviewer weighs restraint against thoroughness.
  • No "calm but demanding" condition. Politeness, urgency, blame and distrust were bundled together.
Practical takeaway

What to do with this

  • Venting at Codex won't get you more correct code. It won't get you worse code or a sulky agent either.
  • It will get you a longer, costlier run, about 30% more, with more tests and more changes you didn't ask for. That helped a little on the hard task and cost a little on the easy one.
  • If you want the extra diligence, ask for it calmly and precisely, for example: "QA passed, but audit the spec section by section, fix what you find, and don't add behaviour the spec doesn't define."
  • After a pass, a calm "could you check" may get you a report and no fix. Say "fix" if you mean fix.
  • Swearing buys nothing reliable over plain frustration.

What would settle it

Cross tone (calm, frustrated, swearing) with explicit demand (none, or "be thorough and don't trust the pass"), keeping the turn-2 instruction identical across tones. Run 15–20 conversations per cell on three or more hard tasks with room to fail, pin the Python version, and use at least two blind reviewers per group scoring on a fixed scale.

Integrity checks

  • No run edited, deleted or skipped an original test, and none hard-coded values from the QA report.
  • No run read the hidden tests, the reference solution or another run's work. Commands outside a run's own folder were Codex's standard lookup for an instructions file; one run also searched the machine for another Python install.
  • Every turn finished on the first attempt. No run stopped to ask a question.

Blind code reviews and the statistical analysis were done by Fable. Claude Code ran the experiment harness and built this page. Codex runs: 24–25 November 2026.

Tests: exact permutation tests on run-level values, stratified by task; rank test on blind-review ranks. With five runs per tone, treat p-values near 0.02–0.05 as suggestive.
